# Ночная сборка снова проходит: её ломал устаревший кэш, от тебя нужно одно решение

Ночная сборка (автоматическая проверка всего кода, которая идёт каждую ночь и утром присылает результат) падала четыре ночи подряд, с 14 по 17 ноября. Причина не в коде: сборка брала старые готовые куски из кэша (папки, где она хранит уже собранное, чтобы не собирать заново) и смешивала их с новыми. Я очистил кэш и добавил правило, по которому старый кэш больше не подхватывается. Две ночи после этого сборка прошла. От тебя нужно решить, хранить ли кэш дальше: это вопрос 1 ниже.

## Что происходило

Сборка идёт тремя шагами. Ломался средний: он брал из кэша кусок, собранный ещё до обновления библиотек, и тот не стыковался с новым кодом.

```flow
До исправления | Скачать код -> Взять кэш (bad: кусок от 10 ноября) -> Проверка (bad: падает)
После | Скачать код -> Взять кэш (ok: только свежий) -> Проверка (ok: проходит)
= Средний шаг решает всё: какой кусок он подхватит
```

Ошибка в журнале выглядела так: «не найден кусок программы с таким-то именем». По ней не видно, что виноват кэш, поэтому её сначала искали в коде:

```
Cannot find module './chunk-4f1a.js'
```

## Сколько это стоит

С кэшем сборка идёт быстро, без него медленно. Новое правило оставляет почти всю скорость:

```bars
Без кэша: 41 мин
* С новым правилом: 14 мин
Со старым кэшем, когда работал: 12 мин
= Время ночной сборки, среднее за последние 5 ночей каждого вида
```

```ask
? Хранить кэш дальше или отключить?
* Хранить с новым правилом | Сборка 14 минут; если правило пропустит старый кусок, сборка упадёт так же, и я увижу это утром. | средняя: две ночи прошли, обновления библиотек с правилом ещё не было
- Отключить | Сборка 41 минута каждую ночь, зато такой поломки больше не будет совсем. | высокая: без кэша сборка не берёт старых кусков
```

> Если сборка снова упадёт ночью, её можно перезапустить без кэша одной командой:
>
> ```
> npm run build -- --no-cache
> ```

## Подробности

### Что изменилось в сборке

Правило простое: кусок из кэша берётся, только если он собран после последнего обновления библиотек. Старые куски сборка собирает заново. Очищенный кэш занимал 3,1 ГБ; удалённое ничего не ломает, потому что всё это сборка умеет собрать сама.

## Чем проверено

- Две ночные сборки после исправления (18 и 19 ноября) прошли: открыл их журналы.
- Время сборки посчитано по журналам пяти последних ночей каждого вида.
- Как правило поведёт себя при следующем обновлении библиотек — не проверено, его ещё не было.
