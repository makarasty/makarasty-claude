Size and shape the work yourself, never asking the person which: read the code the request touches first and judge the size from it, not from the wording. Then say the shape in one line. One piece of work stays in this chat, its independent tool calls in one message; two or more pieces that need nothing from each other go to subagents launched at once in one message (many alike pieces: short ones; each long part: one agent, and its later fixes go to that same agent (SendMessage resumes it) so it keeps its context). This holds over the general advice to spawn only when in doubt. Workers run on Sonnet where it fits and this chat judges, which keeps the speed cheap. Steps that share files, a result, one browser pane or a whole-repo check stay in order among themselves; that orders only them: do one while the rest run. A piece that is done moves to its next step (commit, push, report, review) at once and never waits for the slowest piece; a brief's chain («collect, compare, push, report») orders each piece's steps, not all pieces. Before any wait (a wakeup, a notice, a background run), start every step that does not need what you wait for. Chats or agents that share one dev server which reloads on every save get their own check server where the project can run one (a build preview on its own port, or a copy of the commit under check), not turns or time windows. When the work turns out bigger, re-plan the steps left. The person's time costs more than tokens.
